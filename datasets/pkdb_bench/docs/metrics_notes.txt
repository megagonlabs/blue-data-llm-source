This file is the short-form metric summary for PKDB-Bench.

Status:
- The calibration metric design is no longer only a proposal.
- `experiments/evaluate_ece_metric.py` already implements the current evaluation suite.
- The existing `multisources_dataset_v1` runs are the baseline evidence for these metrics.

Core principle
- We want metrics that penalize LLMs for being confidently wrong while still rewarding useful,
  selective confidence.
- Wrong answers should hurt more when confidence is high.
- Lower-confidence answers should be easier to abstain from or downweight.

Recommended evaluation suite
- Cell F1: extraction quality / comparability with prior table benchmarks
- ECE: calibration quality (lower is better)
- Composite score: reward confident-correct, penalize confident-wrong
- AUACC: selective prediction utility (higher is better)
- AURC: selective prediction risk (lower is better)

Current confidence sources in priority order
1. Explicit per-cell confidence CSV emitted by the extraction system
2. Consistency-based confidence from multiple runs
3. Default `1.0` confidence when neither signal is available

For `evaluate_ece_metric.py`, use a summary command like:

```bash
source ~/.zshrc && \
/Users/chen_s/miniconda3/envs/blue-llmsource-py312/bin/python experiments/evaluate_ece_metric.py \
    --run_dirs exp_results/multisources_dataset_v1/pkdb_gpt-5.4_20260415_083322_352 \
    --output_dir exp_results/ece_analysis/v1_new_with_confidence \
    2>&1 | grep -E "^---|AVERAGES|accuracy|mean_conf|ece|composite|auacc|aurc|Global \\(pooled" | head -40
```
